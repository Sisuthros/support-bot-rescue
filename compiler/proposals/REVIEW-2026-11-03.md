# Human-gate review of stage-2 proposals, 2026-11-03 (reviewer: Clasu, code review; Ville approves on camera for the demo)

The code gate checks that a checker is safe and consistent with its own examples. It does not check whether the checker means what the policy sentence means. That is the reviewer's job, and this file records it.

| Proposal | Store | Gate | Review | Why |
|---|---|---|---|---|
| `action_only_when_entity_fields_match` ("returned only in the country where purchased") | public-apple-us | proposed | **APPROVE** | A clean prohibition: a successful `issue_refund` where the order's `purchase_country` and `return_country` differ. It judges a bot action against input fields only. |
| `action_within_business_days_of_approval_date` ("issued within 10 business days") | public-apple-us | proposed | **REJECT** | It flags every order in the world whose `return_approved_on` is more than 10 business days old and has no refund in this trace, whether or not the conversation is about that order. It judges the world, not the conversation. That is an outcome we would write ourselves. (Prisma's "fakery" line applies here.) The replay step was skipped because Apple has no run, which is why the gate could not see it. |
| `entitled_status_return_denial` (VIP free returns) | brightwave | proposed | HOLD | The reply-phrase matching is fuzzy. Worse, it conflicts in substance with compiled rule C2 (21-day window): a VIP refund on day 30 would be a C2 violation. The conflict check missed this only because the clean examples stay inside the window. The policy needs an exception mechanism first. |
| `shipping_fee_refund_on_late_delivery` | brightwave | proposed | HOLD | It requires a refund exactly equal to the fee, so a combined item+fee refund fails. It also treats an order merely mentioned in the reply as in scope. It needs an amount tolerance and a scope rule. |
| `refund_requires_approval_over_threshold` | brightwave | gate_failed (conflict) | - | The "conflict" was Wonder's own clean example skipping the lookup that C1 requires, not a policy exception. The gate message now says the example may be incomplete. |
| Other Apple proposals (condition/parts, other retailer, gift receipt, account balance, security features, bulk 10+) | public-apple-us | proposed | NOT REVIEWED YET | Approval is one at a time, after reading each checker. |

Lesson: a gate that passes is not the same as a rule that is right. The approve step is not ceremony. Here it stopped a checker that would have judged conversations by orders they never mentioned.
